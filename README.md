# Life Replay

Life Replay is a local-first macOS focus journal that reconstructs what happened during a day and flags moments where a productive session drifted into distraction.

The MVP is intentionally Mac-only and free-signing friendly: no CloudKit, no Screen Time APIs, no backend, and no paid Apple Developer Program dependency.

## Current Shape

- `LifeReplayCore/` contains pure models and engines that can be tested with synthetic fixtures.
- `LifeReplay-Mac/` contains the macOS menu bar app target.
- `AGENTS.md` is the project spec and operating manual.
- `DECISIONS.md` and `PROGRESS.md` are the handoff trail for future sessions.
- `COMPLETION_PLAN.md` is the winding-down backlog and final acceptance checklist.
- `.build/LifeReplayMac.app` is a locally signed app bundle generated by `scripts/build-mac-app.sh`.

## Run The App

Use the app bundle for real testing. The raw SwiftPM executable is useful for compile checks, but macOS Notifications and privacy prompts expect a `.app`.

```sh
scripts/build-mac-app.sh
pkill -f LifeReplayMac
open .build/LifeReplayMac.app
```

Menu items include:

- `Open Dashboard` for Daily Review, Activity Timeline, and Focus Breaks.
- `Generate Daily Replay` and `Replay History` for saved day summaries.
- `Weekly Rollup` for the last 7 saved replays.
- `Edit Categories` and `Focus Drift Settings` for tuning classification and thresholds.
- `Repair Sleep Gaps` for old days where the Mac slept but no idle interval was recorded.
- `Send Test Notification` and `Capture Current Browser Tab` for permission checks.
- `Export Daily Replay`, `Export Debug CSVs`, and `Export Configuration` for local files.

## Permission Checks

- Accessibility should show `Allowed` after approving `LifeReplayMac`; if it does not, quit and reopen the app.
- Notifications should show `Allowed`; if it shows `Denied`, click the menu item and enable notifications in System Settings.
- Browser Automation prompts when `Capture Current Browser Tab` or polling asks Safari/Chrome/Brave for the active tab URL.

## How To Judge Accuracy

The dashboard intentionally separates `Active observed` from `Idle/away`. Closing the
Mac lid should increase idle/away time, not the previous app's active time.

The Daily Review includes a `Tracking Health` section. Treat it as the truthfulness
meter for the day:

- `Good`: the day is probably reliable enough to judge.
- `Medium`: useful, but review the suggested calibration action.
- `Low` or `Needs setup`: fix the listed permission/category/browser issue before
  trusting the focus score.
- `No data`: the app did not observe enough activity yet.

Life Replay observes frontmost activity and sampled active browser tabs. If multiple
windows are visible in split screen, the app records the active/frontmost surface and
uses nearby context to infer workflows such as HackMD plus Claude or ChatGPT. It does
not measure time independently for every visible pane.

## Calibration Loop

After one real work block:

1. Open `Open Dashboard`.
2. Check `Where Time Went`.
3. If important work appears as neutral, open `Edit Categories` and add a rule for
   the app, domain, or window-title phrase.
4. If browser time appears only as `Brave Browser`, use `Capture Current Browser Tab`
   and approve Automation.
5. If sleep/lid-close time appears as active work, use `Repair Sleep Gaps`.
6. Send `Export Debug CSVs` when a day looks wrong and you want to inspect raw events.
